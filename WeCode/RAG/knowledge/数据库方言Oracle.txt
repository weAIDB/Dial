一、语法差异：从书写习惯到执行行为

1.1 别名定义与引用：
1. 自然语言问题中通常需要用到该语法的情况：
   - 查询结果列需要更易理解的名称（如"显示员工姓名和年薪"中的"年薪"）
   - 处理复杂表达式时需要简化引用（如"计算每个部门的平均工资"中的"平均工资"）
   - 多表关联时需要区分相同列名（如"显示订单和客户名称"中的"客户名称"）
   - 包含特殊字符或空格的列名（如"显示年度总收入"中的"年度总收入"）

2. 相关功能描述：
   - 支持使用AS关键字定义列别名
   - 提供多种别名定义语法（如SQL Server的=语法）
   - 支持带空格和特殊字符的别名（使用双引号或反引号）
   - 允许在查询其他部分引用已定义的别名

* AS 关键字： 最通用的标准做法。

 	--Oracle (推荐)L

 	SELECT first\_name AS fn, last\_name AS ln FROM employees;


* 双引号别名： 当别名包含空格、特殊字符或需要区分大小写时使用。

 	-- Oracle

 	SELECT salary AS "Annual Salary" FROM employees;



* 单引号错误尝试： 在绝大多数DBMS中会导致错误或非预期的字符串输出。

 	-- 错误或非预期 (可能被解释为字符串，导致返回两列相同的字符串)

 	SELECT salary 'Annual Salary' FROM employees; -- 不推荐，易错

   - 提供正则表达式模式匹配提取复杂格式的字符串片段
   - 实现基于分隔符位置的子串截取和提取

   (3)Oracle:

--方法1：

语法：REGEXP\_SUBSTR(source\_char, pattern \[, position \[, occurrence \[, match\_parameter]]])，

参数：source\_char：源字符串（如'a:b:c'）。pattern：正则模式（示例 '\[^:]+' 表示 “非 : 的连续字符”，即分隔符外的子串）。position：从源字符串第几个字符开始匹配（默认 1，即开头）。occurrence：提取第几个匹配的子串（默认 1，即第一个）。match\_parameter：正则匹配参数（可选，如 'i' 不区分大小写）。

eg：REGEXP\_SUBSTR('a:b:c', '\[^:]+', 1, 2) → 返回 'b'（匹配 “非 : 的子串”，取第 2 个匹配）。

--方法2：

INSTR 语法：INSTR(source\_char, search\_char \[, start\_position \[, occurrence]])（找分隔符位置）。

SUBSTR 语法：SUBSTR(source\_char, start\_position \[, length])（截取子串）。

逻辑：用 INSTR 找到第 n 个分隔符的位置，再用 SUBSTR 截取到该位置的子串。

eg（取第 1 部分）：

SUBSTR('a:b:c', 1, INSTR('a:b:c', ':', 1, 1) - 1) → 返回 'a'（从开头截取到第 1 个 : 之前）。

* 递归CTE能力：

  (1)所有平台均支持，是处理树状结构（组织架构、分类目录）、图遍历的理想选择。

      示例：查找员工及其所有下属（递归无限层）：

      		-- 初始节点 (Anchors)

      		SELECT id, name, manager\_id, 0 AS level

      		FROM employees WHERE manager\_id IS NULL

      		UNION ALL

      		-- 递归成员 (Recursive Member)

      		SELECT e.id, e.name, e.manager\_id, eh.level + 1

      		FROM employees e

      		INNER JOIN EmployeeHierarchy eh ON e.manager\_id = eh.id

   	)

   	SELECT \* FROM EmployeeHierarchy ORDER BY level, name;
