 	-- Oracle

    	SELECT SYSTIMESTAMP FROM DUAL; -- Precise timestamp (microsecond level)

      Get current date (truncate time): SELECT TRUNC(CURRENT_DATE) FROM dual; (Result e.g., 2025-11-19)
      Extract current year: SELECT EXTRACT(YEAR FROM CURRENT_DATE) FROM dual; (Result: 2025)
      Compare with SYSDATE: SELECT CURRENT_DATE, SYSDATE FROM dual;

1.6.1 Two-Table Joins
* INNER JOIN: Recommended standard form
     SELECT e.name, d.department_name
     FROM employees e
     INNER JOIN departments d ON e.dept_id = d.id; -- Clearly expresses the join condition

* Old-style comma list + WHERE: Legacy style (not recommended, poor readability, error-prone)
     SELECT e.name, d.department_name
     FROM employees e, departments d
     WHERE e.dept_id = d.id; -- Implicit inner join, easy to forget conditions leading to Cartesian products

* (+): Oracle-specific outer join marker (legacy syntax)
     -- Oracle (Not recommended, should use standard OUTER JOIN instead)
     SELECT e.name, d.department_name
     FROM employees e, departments d
     WHERE e.dept_id = d.id(+); -- Indicates a RIGHT OUTER JOIN (pay special attention to symbol placement)

Important: All modern versions recommend using explicit LEFT/RIGHT/FULL OUTER JOIN syntax.

- Aggregate Function (MAX()/AVG() etc.) Handling of NULL Values
-- Oracle:
   Method:
   MAX()/MIN()/AVG()/SUM() ignore NULL values by default; COUNT(column) ignores NULLs, COUNT(*) counts all rows;
   Explicitly excluding NULLs can reduce the amount of data scanned during aggregation when the column has a NOT NULL constraint or an index, leading to better performance;
   In conditional aggregation, `AVG(DECODE(condition, column, NULL))` is equivalent to a CASE expression, NULLs do not participate in the calculation.
   eg:
   SUM() ignores NULL: `SELECT SUM(bonus) FROM employees;` (employees with NULL bonus do not contribute to the sum)
   Explicitly filters NULL: `SELECT AVG(hgb) FROM patient WHERE hgb IS NOT NULL;` (avoids returning NULL when all values are NULL)
   Conditional aggregation (DECODE): `SELECT AVG(DECODE(department, 'IT', salary, NULL)) FROM staff;` (only calculates the average salary for the 'IT' department)

2. Relevant Function Description:
   - Splits a string by a specified delimiter and returns the substring at the specified position
   - Supports counting and extracting segments from the beginning or end of the string
   - Provides regular expression pattern matching for extracting complex format string segments

(1)Oracle:
-- Method 1:
Syntax: `REGEXP_SUBSTR(source_char, pattern [, position [, occurrence [, match_parameter]]])`,
Parameters: source_char: source string (e.g., 'a:b:c'). pattern: regex pattern (example '[^:]+' means "consecutive characters not :", i.e., substrings outside the delimiter). position: start matching from which character of the source string (default 1, i.e., start). occurrence: extract the occurrence-th matching substring (default 1, i.e., first). match_parameter: regex matching parameters (optional, e.g., 'i' for case-insensitive).
eg: `REGEXP_SUBSTR('a:b:c', '[^:]+', 1, 2)` → returns 'b' (matches "substrings not containing :", takes the 2nd match).
-- Method 2:
INSTR syntax: `INSTR(source_char, search_char [, start_position [, occurrence]])` (finds delimiter position).
SUBSTR syntax: `SUBSTR(source_char, start_position [, length])` (extracts substring).
Logic: Use INSTR to find the position of the n-th delimiter, then use SUBSTR to extract the substring up to that position.
eg (get 1st part):
`SUBSTR('a:b:c', 1, INSTR('a:b:c', ':', 1, 1) - 1)` → returns 'a' (extract from start to before the 1st :).
